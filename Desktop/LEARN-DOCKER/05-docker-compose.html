Módulo 05

Docker Compose

Levantar una app real casi nunca es un solo contenedor: es una app + una base de datos + quizás un caché. Encadenar comandos docker run a mano se vuelve inmanejable rápido. Compose resuelve eso.

05.1 Qué problema resuelve

Analogía de la partitura

Si cada contenedor es un instrumento, Docker Compose es la partitura que le dice a la orquesta completa qué tocar, en qué orden y cómo coordinarse —en vez de darle instrucciones por separado a cada músico (cada docker run), escribes una sola partitura (docker-compose.yml) y toda la orquesta arranca sincronizada con un solo comando.

05.2 Anatomía de un docker-compose.yml

docker-compose.yml
services:
  web:
    build: .
    ports:
      - "3000:3000"
    environment:
      - DB_HOST=db
      - NODE_ENV=production
    depends_on:
      - db
    volumes:
      - .:/app
    restart: unless-stopped

  db:
    image: postgres:16-alpine
    environment:
      - POSTGRES_PASSWORD=secreto
      - POSTGRES_DB=miapp
    volumes:
      - datos-db:/var/lib/postgresql/data
    restart: unless-stopped

  redis:
    image: redis:alpine
    restart: unless-stopped

volumes:
  datos-db:
ClaveQué define
servicesCada contenedor de tu aplicación, con su propio nombre lógico
buildConstruye la imagen desde un Dockerfile local (en vez de descargarla)
imageUsa una imagen ya publicada, sin necesidad de Dockerfile
portsMapeo host:contenedor, igual que -p en docker run
environmentVariables de entorno, igual que -e
depends_onOrden de arranque — no espera a que el servicio esté "listo", solo a que el contenedor exista
volumesPersistencia de datos, definidos también a nivel de archivo
restartPolítica de reinicio automático ante fallos
depends_on no espera a que la app esté lista

Solo espera a que el contenedor arranque, no a que Postgres termine de inicializar internamente. Para dependencias reales, usa healthcheck + condition: service_healthy, o lógica de reintento dentro de tu app.

05.3 Comandos de Compose

bash
# Levantar todos los servicios (crea, construye si hace falta, y arranca)
docker compose up

# En segundo plano
docker compose up -d

# Reconstruir imágenes antes de levantar (tras cambiar el Dockerfile)
docker compose up --build

# Ver el estado de los servicios
docker compose ps

# Logs de todos los servicios, en vivo
docker compose logs -f

# Entrar a un servicio específico
docker compose exec web bash

# Detener y eliminar contenedores, redes (mantiene los volúmenes)
docker compose down

# Lo mismo, pero también elimina los volúmenes (¡borra los datos!)
docker compose down -v

05.4 Variables de entorno con .env

Compose lee automáticamente un archivo .env en el mismo directorio y sustituye las variables dentro del YAML. Así separas configuración de secretos del archivo versionado en git.

.env
DB_PASSWORD=secreto_real
APP_PORT=3000
docker-compose.yml (fragmento)
services:
  web:
    ports:
      - "${APP_PORT}:3000"
    environment:
      - DB_PASSWORD=${DB_PASSWORD}
Regla de oro

El archivo .env con secretos reales va en .gitignore. Versiona en su lugar un .env.example con las claves sin valores sensibles, como plantilla para el equipo.
