Módulo 01

Instalación y arquitectura

Antes de escribir un solo comando, vale la pena entender qué piezas están hablando entre sí cuando escribes docker run. Te ahorrará confusión más adelante.

01.1 Cliente–Daemon: quién manda a quién

Docker no es un solo programa: es un sistema cliente-servidor. Cuando escribes un comando en tu terminal, no estás ejecutando el contenedor directamente.

Analogía del capitán de puerto

El Docker CLI (lo que tú escribes) es como un operario en el muelle que da órdenes por radio. El Docker Daemon (dockerd) es el capitán de puerto: el que realmente controla las grúas, coordina el almacén de contenedores (imágenes) y decide qué se mueve y cuándo. Tú nunca tocas las grúas directamente —solo le hablas al capitán, y él ejecuta.

Esto es útil de recordar cuando algo falla: si el "capitán" (daemon) no está corriendo, ningún comando funcionará, sin importar qué tan bien escrito esté.

01.2 Instalación por sistema operativo

Windows y macOS: Docker Desktop

La forma recomendada para desarrollo local. Incluye el daemon, el CLI, y una interfaz gráfica. En Windows requiere WSL2 (Subsistema de Windows para Linux) como backend, ya que el daemon de Docker corre nativamente sobre Linux.

  1. Descarga el instalador desde docker.com/products/docker-desktop.
  2. En Windows: habilita WSL2 si el instalador te lo pide (wsl --install desde PowerShell como administrador).
  3. Reinicia y abre Docker Desktop — espera a que el ícono de la ballena deje de animarse.

Linux: Docker Engine

En Linux no necesitas Docker Desktop: instalas el motor directamente. Ejemplo para Ubuntu/Debian:

bash
# 1. Quitar versiones antiguas si existen
sudo apt-get remove docker docker-engine docker.io containerd runc

# 2. Instalar dependencias y añadir el repositorio oficial
sudo apt-get update
sudo apt-get install ca-certificates curl gnupg
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg

# 3. Instalar Docker Engine + CLI + Compose plugin
sudo apt-get install docker-ce docker-ce-cli containerd.io docker-compose-plugin

# 4. (Opcional pero recomendado) usar docker sin sudo
sudo usermod -aG docker $USER
# cierra sesión y vuelve a entrar para que aplique

01.3 Verificar la instalación

bash
docker --version
# Docker version 27.x.x, build xxxxxxx

docker run hello-world
# Descarga una imagen mínima y confirma que todo el flujo funciona:
# CLI → daemon → descarga de imagen → contenedor ejecutado → mensaje impreso
Qué acaba de pasar

docker run hello-world es la mejor prueba de humo posible: obliga al daemon a buscar la imagen localmente, no encontrarla, descargarla de Docker Hub, crear un contenedor a partir de ella, ejecutarlo, imprimir un mensaje y terminar. Si ves el mensaje de confirmación, tu instalación completa —CLI, daemon y red— funciona.

01.4 Docker Desktop vs. Docker Engine, ¿cuál uso?

EscenarioRecomendación
Desarrollo en laptop (Win/Mac)Docker Desktop — incluye GUI, gestión de recursos y WSL2 integrado
Servidor Linux / producciónDocker Engine directo — sin overhead de interfaz gráfica
CI/CD (GitHub Actions, GitLab CI)Docker Engine, normalmente ya preinstalado en el runner
WSL2 en Windows sin DesktopDocker Engine instalado directamente dentro de la distro WSL2
Nota de licencia

Docker Desktop requiere licencia paga para empresas grandes (más de 250 empleados o 10M+ USD de ingresos). Docker Engine en Linux es y siempre ha sido gratuito y de código abierto. Si trabajas en una empresa, vale la pena confirmar cuál aplica.
