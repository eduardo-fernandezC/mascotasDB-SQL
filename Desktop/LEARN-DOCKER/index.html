Docker: de cero a profesional

Un contenedor de carga estandariza el transporte de cualquier mercancía en cualquier barco, grúa o camión del mundo. Docker hace exactamente lo mismo con tu software: lo empaqueta en una unidad estándar que corre igual en tu laptop, en el servidor del equipo y en la nube. Esta guía te lleva desde el primer docker run hasta prácticas reales de producción.

00.1 ¿Qué es Docker, exactamente?

Docker es una plataforma que empaqueta una aplicación junto con todo lo que necesita para funcionar —dependencias, librerías, configuración, versión exacta del runtime— en una unidad llamada contenedor. Ese contenedor se ejecuta de forma aislada, pero comparte el kernel del sistema operativo anfitrión, lo que lo hace mucho más liviano que una máquina virtual completa.

Analogía del puerto

Antes de los contenedores de carga estandarizados (años 50), cada barco cargaba mercancía suelta: sacos, cajas, barriles, de formas y tamaños distintos, cada uno estibado a mano de manera diferente. Cargar un barco tomaba días. Con el contenedor ISO estándar, cualquier grúa del planeta sabe exactamente cómo tomarlo, cualquier camión sabe cómo transportarlo, y no importa qué haya adentro. Docker aplica esa misma idea al software: no importa si tu app es Python, Node o Java —una vez en un contenedor, cualquier servidor con Docker sabe exactamente cómo "moverlo" y ejecutarlo.

00.2 Contenedores vs. Máquinas Virtuales

Esta es la pregunta que todo principiante se hace. La diferencia está en qué tan "abajo" se hace el aislamiento.

🏠 Máquina Virtual

App A
Librerías / Bins
Sistema operativo invitado
Hipervisor
Hardware / Host OS

Cada VM incluye su propio sistema operativo completo. Es como construir una casa entera —con su propia agua, luz y estructura— para cada inquilino. Pesado (GBs) y lento de iniciar (minutos), pero con aislamiento total.

📦 Contenedor Docker

App A
App B
App C
Motor Docker
Kernel del Host OS (compartido)

Los contenedores comparten el kernel del sistema anfitrión. Es como un edificio de departamentos: cada uno tiene su espacio privado y aislado, pero comparten la misma infraestructura del edificio. Livianos (MBs) y arrancan en segundos.

En una frase

La VM virtualiza el hardware. Docker virtualiza el sistema operativo. Por eso un contenedor pesa megabytes y arranca en segundos, mientras una VM pesa gigabytes y arranca en minutos.

00.3 Los tres conceptos que lo sostienen todo

  • Imagen: la plantilla de solo lectura —como la receta de una comida. No cambia.
  • Contenedor: una instancia en ejecución de una imagen —el plato ya servido a partir de esa receta. Puedes crear muchos contenedores idénticos a partir de una sola imagen.
  • Registro (registry): el almacén donde viven las imágenes —Docker Hub es el más conocido, como una biblioteca pública de recetas.
