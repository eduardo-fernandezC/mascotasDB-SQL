Módulo 02

Comandos esenciales

Estos son los comandos que vas a escribir todos los días. Están agrupados por el ciclo de vida real de un contenedor: crear, observar, intervenir, y limpiar.

02.1 El ciclo de vida de un contenedor

Analogía

Un contenedor no es una máquina que "enciendes y apagas" como una VM: es más como un proceso desechable. Se crea a partir de una imagen, corre mientras tiene un trabajo activo (un proceso en primer plano), y en el momento en que ese proceso termina, el contenedor se detiene —igual que una calculadora que se apaga sola cuando terminas la operación. Por eso los contenedores están pensados para ser efímeros y reemplazables, no para "mantenerse vivos" a mano.

02.2 Crear y ejecutar

docker run

Crea un contenedor nuevo a partir de una imagen y lo inicia. El comando más usado de todo Docker.

-d segundo plano (detached) -it interactivo + terminal -p mapea puertos --name le pone nombre --rm se autoelimina al parar -v monta un volumen -e variable de entorno
bash
# Servidor web nginx, en segundo plano, puerto 8080 del host → 80 del contenedor
docker run -d -p 8080:80 --name mi-web nginx

# Ubuntu interactivo: entras directo a una terminal dentro del contenedor
docker run -it ubuntu bash

# Se ejecuta, cumple su función, y se borra solo al terminar
docker run --rm alpine echo "hola desde un contenedor efímero"
Diferencia clave

docker run siempre crea un contenedor NUEVO. Si solo quieres reanudar uno que ya existe, usa docker start — es un error común ejecutar run repetidamente y terminar con diez contenedores nginx apilados.

02.3 Observar lo que está corriendo

docker ps

Lista los contenedores en ejecución. Con -a, muestra también los detenidos.

docker logs

Muestra la salida (stdout/stderr) de un contenedor. Con -f, la sigue en vivo, como tail -f.

docker inspect

Vuelca toda la metadata de un contenedor o imagen en JSON: IPs, volúmenes, variables de entorno, todo.

docker stats

Muestra CPU, memoria y red en tiempo real, contenedor por contenedor. Tu "administrador de tareas" de Docker.

bash
docker ps
CONTAINER ID   IMAGE   STATUS          PORTS                  NAMES
a1b2c3d4e5f6   nginx   Up 5 minutes    0.0.0.0:8080->80/tcp   mi-web

docker ps -a          # incluye los detenidos
docker logs -f mi-web   # sigue el log en vivo, Ctrl+C para salir
docker stats            # uso de recursos en tiempo real

02.4 Intervenir un contenedor corriendo

docker exec

Ejecuta un comando dentro de un contenedor que YA está corriendo. Ideal para "entrar" a inspeccionar sin detener nada.

docker cp

Copia archivos entre tu máquina y el contenedor, en cualquier dirección.

bash
# Abrir una terminal DENTRO de un contenedor ya corriendo
docker exec -it mi-web bash

# Ejecutar un solo comando sin entrar interactivamente
docker exec mi-web cat /etc/nginx/nginx.conf

# Copiar un archivo desde el host hacia el contenedor
docker cp ./index.html mi-web:/usr/share/nginx/html/index.html
exec vs. run

docker run es abrir un contenedor nuevo desde cero. docker exec es tocar la puerta de un contenedor que ya está en marcha y asomarte adentro sin interrumpir lo que estaba haciendo —como entrar a una oficina que ya está en horario laboral, en vez de construir una oficina nueva.

02.5 Detener, iniciar, eliminar

ComandoQué hace
docker stop <id>Detiene el contenedor de forma ordenada (envía SIGTERM, espera, luego SIGKILL)
docker kill <id>Lo detiene de inmediato (SIGKILL directo, sin gracia)
docker start <id>Reinicia un contenedor detenido, conservando su estado
docker restart <id>Detiene e inicia de nuevo en un solo paso
docker rm <id>Elimina un contenedor detenido (agrega -f para forzar si está corriendo)

ComandoQué hace

docker rmi <imagen>Elimina una imagen local
docker tagLe pone una etiqueta/alias a una imagen
docker pushSube una imagen a un registro (Docker Hub u otro)

02.7 Limpieza del sistema

Con el tiempo se acumulan imágenes, contenedores detenidos y redes huérfanas que ocupan espacio en disco silenciosamente.

bash
# Elimina contenedores detenidos, redes sin usar, y caché de build
docker system prune

# Lo mismo, pero también elimina imágenes sin usar (más agresivo)
docker system prune -a

# Ver cuánto espacio está usando Docker en total
docker system df
Cuidado

docker system prune -a borra TODAS las imágenes que no tengan un contenedor corriendo asociado. Si tienes imágenes que descargaste para usar después, revisa dos veces antes de confirmar.
